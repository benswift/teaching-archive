### Spotify to Raspotify

I tried to port it onto the Raspberry Pi using the Chromium release for Debian. I kept on encountering `initialization error: Player failed to initalize`. As it turns out the Spotify Web SDK relies on [Encrypted Media Extensions](https://developers.google.com/web/fundamentals/media/eme) to run. It's the same technology that facilitates Netflix streaming. In essence it provides an API which abstracts away from the encryption layer allowing content to be streamed securely. As it is an extension not all browsers support it, and the [Spotify docs](https://developer.spotify.com/documentation/web-playback-sdk/#requirements) themselves only say non-Mobile versions of Firefox, Chrome, Edge and IE work.

A (stackoverflow post)[https://askubuntu.com/questions/6253/whats-the-difference-between-google-chrome-and-or-chromium-what-are-the-advant] suggested that Chromium could be augmented to run EMEs. I installed plugins, [here](https://packages.ubuntu.com/search?keywords=chromium-codecs-ffmpeg) and [here](https://packages.ubuntu.com/search?keywords=chromium-codecs-ffmpeg-extra), for Chromium but no luck. I tried to install the closted-source Chrome onto the Pi. It required an x86 operating system so I stopped short of installing Exager, [as this post](https://www.linux.com/blog/run-google-chrome-raspberry-pi) suggested as it felt wrong to map over an already pretty cool piece of tech. Instead I tried installing Firefox, but only the [Extended Support Release](https://www.mozilla.org/en-US/firefox/organizations/) was available, which was not supported by Spotify according to this [blog post](https://community.spotify.com/t5/Other-Partners-Web-Player-etc/Spotify-Web-Player-dropped-support-of-the-last-Firefox-ESR-60-4/td-p/4659568) (The latest verison was the first one they stopped supporting). Everyway I tried it felt as if I was trying to play music with a toothpic. It's a very fragile way to play an instrument and definetly not as the designer intended.

As I want to run the Pi headless when complete, it occured to me the only functionality that the Web SDK was really giving me was control over streaming and track operations (next, previous, pause, play, etc.). I could get the same functionality by establishing a Spotify Connect node, and after further research of the Web API I could do all the same track operations as well.

I used (Raspotify)[https://github.com/dtcooper/raspotify] , a Debian package that thinly wraps (libresoft)[https://github.com/librespot-org/librespot] , a tool to create Spotify Connect nodes, for the Raspberry Pi.
