Last week's blog included more practical work - soldering the equipments, connecting everything together (circuits, pins, wires, cables, power supply and data transmission) and trying to test them on different part of the drum (edge, head or the hole on the shell).

So we've got the data input source (sensors), this week's job is to analyse the data and determine if there is a hit and do that repeatedly.

## Analysing

### Analysing with vibration Sensor

Two different methods were considered: (1). Pick a threshold and report whenever the data exceeds the threshold; (2). Analyse the rolling average of the data and report when the average exceed the threshold.

I wrote some Python code to plot the data inputs in a graph and based on the graph, the better idea is to **identify the pattern of the wave when the drum is hit.**

The derivative of the sound data input is calculated. Even though the noise issue still exists, the rapid change of data caused by the hit is much larger than the change of the noise. Thus the hit is detected!

### Analysing with microphone

The data input from the microphone is a lot better than the vibration sensor - far more rich and covers the exact frequency range that we care about (wow drum kits are for performing of course microphone is good why didn't we think of that?!)

Using fourier transform, waves of different frequencies are seperated and thus enable us to distinguish different parts of drum kits. The frequency of the drum kits are kept are constant at this stage because I am just testing on my drum kit. However, for the future use, we need to write more code to read in the start up frequency of the drum kits. For example, ask the user to hit each drum in turn to record the frequency of the actual drum kits they are using.

### Further development

For different techniques like rolling and rim shot instead of a simple hit, more data analysis need to be performed.
